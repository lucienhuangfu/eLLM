### Prefill
- 定义：LLM 推理的第一个阶段，处理完整的输入 prompt 并生成初始的 KV Cache。在 eLLM 中采用 head-by-head 的计算策略，逐个注意力头完成计算以充分利用 CPU 缓存。
- 别名：prefill阶段、预填充

### Decode
- 定义：LLM 推理的第二个阶段，基于已生成的 token 逐步生成下一个 token。每个 decode 步骤只处理单个 token，需要维护历史 KV Cache 的状态。
- 别名：解码阶段、自回归生成

### Slot
- 定义：推理会话的资源单元，代表一个正在处理的请求或会话。每个 slot 包含独立的 KV Cache、状态管理和生命周期控制。支持复用机制以提高资源利用率。
- 别名：槽位、slot管理

### SessionMode
- 定义：会话模式控制，决定 slot 是否允许前缀复用。Reusable 模式下支持 KV Cache 前缀匹配和增量预填充；NonReusable 模式下每次都是全量 prefill。
- 别名：会话模式、session_mode

### KV Cache
- 定义：键值缓存，存储注意力计算中的 Key 和 Value 向量。在 eLLM 中使用静态形状的连续内存布局，避免分页管理的开销，提高内存访问效率。
- 别名：KV缓存、键值缓存

### TTFT
- 定义：Time to First Token，首 token 时间，衡量从接收请求到生成第一个 token 的总延迟。是评估长上下文推理性能的关键指标。
- 别名：首token时间、time-to-first-token

### TPOT
- 定义：Time Per Output Token，每输出 token 的时间，衡量解码阶段的平均延迟。反映模型生成速度的关键性能指标。
- 别名：每token时间、time-per-output-token

### BatchSequence
- 定义：批处理序列管理器，负责协调多个请求的并行执行。维护 batch 级别的温度参数、序列长度等信息，支持动态批处理。
- 别名：批序列、batch_sequence

### ExecutorPool
- 定义：执行器池，管理 worker 线程池执行 operator 任务。将 scheduler 生成的任务分配给空闲的 worker 线程并行执行。
- 别名：执行器池、executor_pool

### Operator Pipeline
- 定义：算子流水线，将 LLM 的前向传播分解为一系列可复用的算子（attention、matmul、norm 等），按依赖关系组织执行。
- 别名：算子流水线、operator_pipeline
